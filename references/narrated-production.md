# 旁白长片制作（工作台任务专用）

工作台发来的任务（`mg-jobs/<id>/brief.md`）和普通 10 秒样片的区别：**任意时长、有本地 TTS 旁白、可竖屏、可带字幕**。
下面这些规则覆盖 SKILL.md 里的默认硬规格，其余铁律照旧（确定性渲染、素材合法、Signature features 不删改）。

## 硬规格（覆盖默认）

| 项 | 工作台任务 |
|---|---|
| 时长 | `request.json.duration`，误差 ≤ 1 帧；**不是** 10 s |
| 画幅 | 16:9 → 1920×1080；9:16 → 1080×1920（竖屏要重排构图，不是裁切） |
| 帧率 | 30 fps（风格卡要求 24 fps 的，如 04/05，也统一 30 fps，用「一拍二」模拟） |
| 音频 | 旁白 + 动作音效 + 曲库配乐（不生成背景音乐），48 kHz 立体声，−14 LUFS，TP ≤ −1 dBTP，`mgw mix` 负责 |
| 成品 | `<job>/final.mp4` |

## 工具：`workbench/mgw`

| 命令 | 作用 |
|---|---|
| `mgw narrate <job>` | 按 `script.json` 合成旁白 → `narration/*.wav` + `manifest.json`（每句时长）。未改动的句子复用缓存；`--only 003,007` 只重做指定句；`--detach` 后台跑 |
| `mgw assemble <job> --starts starts.json` | 把每句放到时间轴上 → `voice.wav`（48 kHz）+ `timeline.json`（每句真实起止）。句子不会重叠，超出片尾会在 warnings 里报 |
| `mgw bgm-list` | 查看曲库（分类、情绪、BPM、人声、段落表） |
| `mgw bgm-render <job>` | `bgm-plan.json` → `music.wav` + `bgm-used.json`，只用曲库里的歌 |
| `mgw mix <job> --music music.wav [--sfx sfx.wav]` | 配乐侧链压低 + 音效层 + 两遍响度到 −14 LUFS → `audio.wav`。`--music-db`（默认 −4）调配乐底量，`--duck-ratio`（默认 6）调压低力度，`--sfx-db` 调音效 |
| `mgw render <job> -- <参数>` | 排队渲染（本机最多 2 条同时） |
| `mgw status <job> <phase> "<msg>"` | 刷新工作台进度面板 |

音色、语速、音高、语气描述都在 `request.json.voice` 里，由用户在工作台定好，**不要改**。
合成走工作台的单一 TTS 进程（同一时刻只驻留一个模型）。工作台没开时 `mgw` 会自己加载模型。

## 写台词

- 本机实测语速（rate=1.0）：中文约 **3.6 字/秒**，英文约 **2.5 词/秒**。rate 越高越快，按比例换算。
- 纯语音总长控制在目标时长的 **70–85%**。开场留 0.5–1.5 s，片尾留 2–4 s 落版。
- 一句一段，中文 8–28 字。句子太长 TTS 容易气息不稳，太碎又会显得机械。
- 只写念得出来的内容：数字写成汉字或常见读法，不用括号注释、表情符号、网址。
- 用户写的是「想法」，不是台词。台词要有结构（钩子 → 展开 → 落点），别把想法原样念出来。

## 长片的画面结构

10 秒样片是一个镜头一口气讲完，长片要分场：

- **每 6–15 s 一个场景**，场景之间用这个风格自己的转场语言（形变、拼贴翻页、像素擦除、玻璃折射……），不要硬切黑场。
- **每 2–4 s 至少一个视觉事件**（入场、强调、镜头运动、粒子），否则观众会觉得画面「停住了」。
- 节拍来自 `timeline.json`：句子开始时让对应的画面出现；关键词可以做文字强调。
- 参考实现是**词汇表，不是模板**。复用它的绘制函数、质感、配色和运动曲线，镜头和叙事按台词重新设计。
- 一个场景一个 `renderScene(t)` 函数，主 `renderAt(t)` 按时间分派，这样几十秒、几分钟都好维护。

## 字幕（request.subtitles = true）

- 在画面层里按 `timeline.json` 渲染，这样是逐帧确定的，也能和风格统一（小螃蟹用黄字深描边，HUD 用等宽字加扫描线，花字风格直接用花字）。
- 安全区：16:9 底部留 8% 高度；9:16 底部留 14%（避开平台 UI），左右各留 6%。
- 中文每行最多约 16 字（9:16）或 22 字（16:9），超了就按标点断行，最多两行。
- 字幕的入场和出场跟着句子起止，可以有 0.1–0.2 s 的淡入淡出，但不能比语音晚出现。

## 配乐（只从曲库里选，**禁止生成背景音乐**）

背景音乐一律用用户的曲库（`MG视频工作台/bgm/`，`mgw bgm-list` 查看）。mgaudio 只用来做**动作音效**，不要用它写配乐。

1. **看歌**：`mgw bgm-list`（可加 `--category 欢快搞怪`、`--q 钢琴`、`--ids a,b`）。每首有分类、情绪、BPM、能量、是否带人声，以及段落表（如 `40-62h` = 40–62 秒是高能量段）。标了「最近用过」的尽量换别的。
2. **选歌来源**：
   - `request.json.music.picked` 有值：**只能用这些歌**，尽量都用上，顺序、放在哪、用哪一段由你按片子的起伏决定。选得太多、片子放不下时，挑最合适的用，并在最后汇报里说明哪几首没用上、为什么（`mgw bgm-render` 会在 warnings 里列出没用上的）。
   - 为空：从整个曲库里自己找，首数不限。
3. **写配乐方案** `bgm-plan.json`：
   ```json
   {"cues":[{"song":"qq-…","start":0,"end":11.2,"from":40.0,"fade_in":0,"fade_out":0.8,"why":"开头钩子，用副歌抓人"},
            {"song":"qq-…","start":11.2,"end":26.5,"from":13.2,"fade_out":0.8,"why":"讲解铺底，平稳"}]}
   ```
   - 按台词和画面的情绪起伏逐段判断该用什么样的伴奏。**不限首数、不限每段长短**：10 秒、15 秒换一首都可以，同一首歌也可以在不同位置用不同段落。
   - `from` 选在歌的段落起点或拍点上（段落表里的数字），激昂处用高能量段，低沉处用低能量段。
   - 换歌点放在场景切换或句子之间的空档（看 `timeline.json`），不要切在一句话中间。接缝处可以叠一个转场音效。
   - 带人声的歌可以用；人声段尽量放在旁白少的地方，旁白密集处会被自动压得更低。
   - 从 0 秒铺到片尾，中间不留空。
4. **出配乐**：`mgw bgm-render <job>` → `music.wav`（每首先统一到同样响度，自动交叉淡化），同时生成 `bgm-used.json` 给工作台显示。方案不合格会直接报错（歌不在曲库、用了用户没选的歌），改好再跑。
5. **动作音效**（可选但推荐）：在 `scene/audio.py` 里用 mgaudio 的 `sfx`（whoosh、pop、impact、click、ding…）按画面动作卡点，导出 `sfx.wav`，长度等于片长。
6. **混音**：`mgw mix <job> --music music.wav [--sfx sfx.wav]`。旁白 > 音效 > 背景音乐；说话时音乐自动压低，整片 −14 LUFS。不要自己做压低和响度。

## 渲染排队

本机最多同时渲染 2 条，配音一次一条。渲染一律用 `mgw render <job> -- <render.mjs 参数>`，它会自动排队；排队时会在 progress.log 写「渲染排队中」，耐心等，不要绕过它直接跑 `node harness/render.mjs` 出整片（`--stills` 静帧检查可以直接跑）。

## 渲染时长预估

- 先用 `--stills` 出静帧，再用 `--from 0 --to 5 --scale 0.5` 试渲 5 秒，按耗时线性外推整片。
- 整片用 `--workers 4`，16 GB 内存别超过 4 个 worker。
- 超过 8 分钟的渲染用 `nohup … > render.log 2>&1 &` 放后台，轮询日志，别让单条命令超时。

## 验收

用真实 ffmpeg 检查：`ffmpeg -hide_banner -i final.mp4 2>&1 | grep -E "Duration|Stream"`。
时长、分辨率、音轨都对，再抽 3 帧看画面和字幕，合格才算 done。
